Read first; the profit-margin reality. Profit = trading edge − (Kalshi fees + model cost). Self-hosting GLM/Kimi only changes the cost term, and at this project's scale it makes cost worse, not better (a rented GPU fleet only beats API pricing past ~240M tokens/day; a trading council runs far below that). Start with Path A. Path B is here only because you asked; treat it as an experiment, not a profit lever.

Path A — Hosted APIs via OpenRouter RECOMMENDED

One account, one key, all three models (Claude + Kimi K2 + GLM-5.2), unified billing. ~15 minutes.

  1. 1 · account Sign up at openrouter.ai.
  2. 2 · credit Add a small prepaid balance (e.g. $20) under Settings → Credits. This is your hard ceiling; you can't be billed past it.
  3. 3 · key Keys → Create Key. Copy the sk-or-... value (shown once).
  4. 4 · paste Put it in ~/council/.env as OPENROUTER_API_KEY=sk-or-... (see the .env table below).
  5. 5 · verify model slugs On the OpenRouter Models page, confirm the exact slugs for Claude, Kimi K2, and GLM-5.2, and tell me; I'll set them in config.yaml (my current values are placeholders).
That's the whole setup for going live. Then I run python scripts/check_connectivity.py and we're connected.

Path B — Self-host GLM-5.2 on a rented GPU OPTIONAL · ADVANCED

Honest cost warning. A production GLM-5.2 (744B MoE) needs a multi-GPU box (≈ several H100/H200). On-demand that's ~$12–30k/month if left running, and cold-starting on demand means loading hundreds of GB of weights before the first token. This will not lower your trading costs at realistic volume. Do this only for privacy/experimentation. Kimi K2 (1T params) is impractical to self-host — keep Kimi on its hosted API even if you self-host GLM.
  1. 1 · rent Create an account on a GPU marketplace; SimplePod, Vast.ai, or RunPod. Rent a box with enough total VRAM for GLM-5.2 at FP8/INT4 (check the model card; expect multi-GPU). Enable persistent storage so you don't re-download weights every restart.
  2. 2 · serve On the box, serve the model with an OpenAI-compatible endpoint (vLLM): 
    pip install vllm
vllm serve zai-org/GLM-5.2 \
  --tensor-parallel-size <#GPUs> \
  --api-key "choose-a-secret" \
  --port 8000
    (Exact HF repo id + flags come from the GLM-5.2 model card; verify before running.)
  3. 3 · expose Get the box's public URL (e.g. https://<host>:8000/v1). Keep it firewalled to your IP.
  4. 4 · tell me Send me the base URL and the secret you chose. I point LiteLLM at it in config.yaml; the reviewer role becomes openai/GLM-5.2 with api_base=<your URL>. No other code changes (that's the whole point of the LiteLLM seam).
Never paste the GPU box's root SSH key or cloud-account credentials to me. I only need the inference endpoint URL + its API secret.

Kalshi account & API REQUIRED FOR TRADING

Needed even in paper mode; the council reads live Kalshi prices to make realistic simulated decisions. No real orders are placed until you explicitly flip to live.

  1. 1 · account Create and verify a Kalshi account (KYC required; US-regulated exchange).
  2. 2 · api access In account settings, generate API credentials (Kalshi uses an API key ID + an RSA private key for request signing). Download the private key file; it's shown once.
  3. 3 · read-only first For paper mode we only use read endpoints (markets, prices, order book). Do not fund the account yet.
  4. 4 · paste Put the key ID + the path to the private key file in ~/council/.env (table below). Keep the private key file chmod 600 and outside git.
  5. 5 · (later, live only) Only when paper results justify it: fund with an amount you can afford to lose entirely, and we enable the guarded execution layer with hard caps + a kill switch.
Check Kalshi's terms on automated/algorithmic trading before going live; confirm bots are permitted on your account type.

Safety checklist before anything touches real money

  1. Weeks of paper-mode P&L showing a real, fee-aware edge; not a few lucky days.
  2. Hard caps wired: max position size, max daily loss, total bankroll cap, kill switch.
  3. Human approval gate on every live order (at least at first).
  4. Keys stored as files with chmod 600, never pasted into chat, never committed.
  5. Your machine's overnight-suspend issue resolved or accounted for; a trading loop must not die mid-position.
